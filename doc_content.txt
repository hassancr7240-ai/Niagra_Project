1. Where It All Started — The Very First PDF
Everything in this project started with a single document: the Krones Contiform C3 SAN Operating Manual — a 506-page PDF for the blow moulding machine that makes plastic bottles on the production line.
That manual contains 12 chapters. Chapters 1 to 11 cover what the machine is, how it works, safety, controls, production, troubleshooting, and installation. Chapter 12 — Maintenance — is the only chapter that matters for this project. It tells you exactly what to check, when to check it, and what state the machine must be in during each check.
Chapter 12 defines 7 time-based maintenance intervals:
TABLE: Interval | Frequency | Machine State | Examples of What to Check
TABLE: 8 hours | Daily | RUNNING | Visual inspection for leaks, noise, damage — machine continues producing
TABLE: 120 hours | Weekly | ALL 3 STATES | Air manifold (running), toothed belt+lubrication+starwheels (stopped), PE sensors+IR lamps+heating filters (powered off)
TABLE: 500 hours | Monthly | STOPPED+OFF | Pneumatic components, rotary joint, stretching unit, neck-ring guide clearance
TABLE: 1500 hours | 3 months | POWERED OFF | Replace activated carbon filter elements, check drive brake
TABLE: 3000 hours | 6 months | STOPPED | Check all servo drives for leakage, test RCD circuit breaker
TABLE: 6000 hours | Yearly | STOPPED+OFF | Guard doors, air conditioner, replace high-pressure filters, Krones annual inspection
TABLE: 30000 hours | 5 years | SPECIALIST | Replace hose lines — authorised professionals only
2. What Was Built First — The CON L3 Bottle Coder 240 Hours PM
The first concrete output that came from studying the Contiform manual was not a Contiform checklist. It was a realisation that someone had already manually built a PM checklist for a different machine on the same line — the Bottle Coder.
The CON L3 Bottle Coder 240 Hours PM document was a one-page Excel-printed PDF created manually by a team member (mserrano). It contains 28 tasks for servicing the laser coder machine that prints dates and batch codes on every bottle coming off Line 3. This document became the proof of concept and the template for the entire system.
2.1 What the CON L3 Bottle Coder 240hr PM Contains
The document is structured exactly as a standard industrial PM checklist. Reading it from top to bottom:
TABLE: Tasks | Area | Phase | What Happens
TABLE: 10–20 | SAFETY | Before anything | Lock Out / Tag Out the machines. Re-check all E-STOP switches and controls.
TABLE: 30–50 | BOTTLE CODER | Verify coding first | Check the bottle is printing the correct message, correct plant line number format XXDDMMMYY HHMM, correct Best By date format DDMMMYYYY.
TABLE: 60–100 | SAFETY | Power down coder | Enter password DLI → Disable Head A → Turn DC Power key switch OFF → Depress red power button → Depress E-STOP.
TABLE: 110–150 | BOTTLE CODER | Inspect laser head | Inspect cables for damage → open rear door for loose connections → check air line → check laser head housing → clean exterior cabinet and head housing.
TABLE: 160–230 | FUME EXTRACTOR | Fume extractor PM | Check operation screen → check vacuum at hose nozzle → turn off DPX → LOTO fume extractor → check filter elements → check BOX filters L011378 → check BAG filters L011362 → check vacuum hose → check cabinet housing.
TABLE: 250–280 | SAFETY | Return to service | Restore fume extractor power → remove all LOTO → re-check all E-STOP switches → follow all GMP procedures.
TABLE: KEY INSIGHT:
The task numbers go 10, 20, 30 — not 1, 2, 3. This is intentional. If a new task needs to be inserted between Task 10 and Task 20 in the future, it can be called Task 15. There is always room. This is standard industrial PM document design.
The two part numbers in the document — BAG filters L011362 and BOX filters L011378 — are the only spare parts this machine requires at the 240-hour service.

Before any automation, this is what someone had to do to create the CON L3 Bottle Coder 240hr PM:

3. How It Evolved — From One Machine to the General System
The initial goal was simple: automate what mserrano did manually. Build a system that generates the 8-hour, 120-hour, 240-hour, and 500-hour checklists for the machines on Line 3 automatically, without anyone having to type tasks into Excel.
But then the conversation changed. The realisation came that the factory does not have just one machine. It has many — blow moulder, bottle coder, dehumidifier, packer, shrink wrapper, labeller, filler, conveyors. Each machine has its own operating manual. Each manual has its own structure. Each uses different chapter numbers, different interval units, and different terminology.
The question became: can we build ONE system that works for ALL of these, not just the ones we have today?
3.1 The Five Challenges That Needed Solving
TABLE: # | Challenge | Example | How the System Solves It
TABLE: 1 | Different chapter numbers per manufacturer | Krones Contiform: Chapter 12 = Maintenance. Krones Variopac: Chapters 11+12+13. eisbär Dehumidifier: Chapter 9. | Register which chapter(s) contain maintenance when onboarding each machine. System looks there — not hardcoded to any chapter.
TABLE: 2 | Different interval units | Krones: every X operating hours. eisbär Dehumidifier: every 3 months. Bottle Coder: every 240 hours. | Store all intervals as hours internally. Convert once at setup. Show in natural language on the PDF.
TABLE: 3 | Machine state grouping | Contiform 120hr PM requires RUNNING tasks, STOPPED tasks, and POWERED OFF tasks — all different access levels. | Every task is tagged with its required machine state. PDF colour-codes sections automatically so the technician never confuses them.
TABLE: 4 | No manual available | Bottle Coder: only the finished PM document exists, not the original equipment manual. | Tasks entered manually into the Task Editor once. From then on the system generates it automatically at any interval.
TABLE: 5 | Safety documents vs maintenance manuals | Variopac Residual Machine Hazards document: lists hazards but gives no maintenance tasks or intervals. | Used only to write safety warning lines inside task descriptions. Does not generate tasks. Flagged clearly as a safety reference document.

5. How to Make PM Documents — The Exact Process
This is the step-by-step process for creating a PM document from any manual. It applies to every machine, every manufacturer, every interval.
5.1 Step 1 — Identify the Maintenance Chapter
Open the manual and find the table of contents. Look for words like: Maintenance, Service, Inspection, Lubrication, Cleaning. Note which chapter number it is:
TABLE: Manual | Chapter to Read | What to Ignore | Number of Intervals
TABLE: Contiform C3 SAN | Chapter 12 only | Chapters 1–11 | 7 intervals
TABLE: Variopac Pro FS | Chapters 11, 12, AND 13 | Chapters 1–10 | 6 intervals (combined)
TABLE: Dehumidifier DAS-E8K.2 | Chapter 9 only | Chapters 1–8, 10–14 | 5 items (simple)
TABLE: Bottle Coder (no manual) | Use the existing PM doc | N/A — no manual | 28 tasks from the doc
TABLE: Any new machine | Find the chapter titled Maintenance/Service | Everything else | Varies — usually 4–8
5.2 Step 2 — Extract the Tasks
Inside the maintenance chapter, find the interval tables. Each interval is listed with: Component, Location, Inspection Criteria, and Work description. Each sentence or instruction becomes one task row. Apply these rules:
Task number: start at 10, go in steps of 10 (10, 20, 30...). Never use 1, 2, 3.
Area: what part of the machine or what type of work? SAFETY / INSPECT / CHECK / CLEAN / LUBRICATE / REPLACE / GENERAL
Action: what physical action? LOCKOUT / CHECK / LISTEN / CLEAN / REPLACE / LUBRICATE / VERIFY / TEST / CONFIRM
Description: the full instruction in CAPITAL LETTERS. Detailed enough that any trained technician can follow it without reading the manual.
Machine State: RUNNING (machine still producing) / STOPPED (machine stopped, still powered) / POWERED_OFF (fully locked out)
Safety flag: YES if the task involves LOTO, E-STOP, power isolation, or entry into a danger zone.
Part number: if the task involves replacing a consumable, include the part number exactly as shown in the manual.
TABLE: How to identify which interval a task belongs to:
Look for these phrases in the manual:
  'Every 8 operating hours' or 'at least once daily'  →  8-hour interval
  'Every 120 operating hours' or 'at the latest after a week'  →  120-hour interval
  'Before starting production' or 'before every production run'  →  Pre-production check
  'During production' or 'while machine is running'  →  Machine must be RUNNING
  'In set-up mode' or 'machine stopped'  →  Machine must be STOPPED
  'While machine is not in operation' or 'fully locked out'  →  Machine must be POWERED OFF
5.3 Step 3 — Convert Calendar Intervals to Hours (Third-Party Machines)
When a third-party manual uses days or months instead of hours, use this conversion table. The conversion assumes one 8-hour shift per day. If the machine runs multiple shifts, adjust accordingly.
TABLE: Manual Says | Calculation | System Stores As | Real Example
TABLE: Every shift / Every day | 1 day × 8hr | 8 hours | Dehumidifier daily display check
TABLE: Every week | 5 days × 8hr | 120 hours | Standard weekly PM
TABLE: Every 2 weeks | 10 days × 8hr | 240 hours | Bottle Coder 240hr PM
TABLE: Every month | ~21 days × 8hr | 500 hours | Monthly deep inspection
TABLE: Every 3 months | ~63 days × 8hr | 1500 hours | Dehumidifier filter change
TABLE: Every 6 months | ~125 days × 8hr | 3000 hours | 6-monthly inspection
TABLE: Every year | ~250 days × 8hr | 6000 hours | Annual inspection
5.4 Step 4 — Add the Standard Header and Footer
Every PM document regardless of machine or interval uses the same header and footer format. This is what makes all documents look consistent and GMP-compliant:
TABLE: HEADER (top of every document):
  Asset Activity: [MACHINE NAME]  [INTERVAL] HOURS PM
  Description:    [MACHINE NAME]  [INTERVAL] HOURS PM
  Actual start date: ___________
  Actual end date:   ___________
  Hours:             ___________
  Comments & Action: ___________
  Team Member(s):    ___________

TASK TABLE (one row per task):
  [Task#] | [Area] | [Action] | [Description] | [Initial] | [Done ☐]

SIGN-OFF SECTION (before footer):
  Technician Name: ___  Supervisor Approval: ___  Date: ___

PARTS TABLE:
  Part Number | UOM | Required Qty | Issued Qty | Pick Location | Mechanic

FOOTER (bottom of every document):
  **** END OF REPORT ****
  GENERAL — PRIOR TO RETURNING TO SERVICE FOLLOW ALL GMP PROCEDURES
  ⚠ Remove all LOTO devices before returning to service
  ⚠ Re-check all E-STOP and control switches
  ⚠ This document must be signed and retained as a maintenance record

7. What They Want — Understanding the Real Ask
Based on the complete conversation from start to finish, here is exactly what they are asking for:
7.1 The Core Ask — In Plain Words
TABLE: They want a system that:
1. Takes any machine operating manual (PDF) — Krones or any other manufacturer
2. Reads the maintenance chapter of that manual
3. Generates a properly formatted PM checklist document (PDF) for every maintenance interval defined in that manual
4. Saves those documents to a shared location (Azure Blob Storage or FTP) where the team can access them

They are NOT asking for a CMMS (Computerised Maintenance Management System) replacement
They are NOT asking for real-time machine monitoring or sensor integration

They are NOT asking for the system to read PDFs fully automatically — manual task entry for third-party machines is acceptable
